# 项目开发约定（saki-dev）格式与生成指南

本文配合 `saki-govern` 使用。开发约定是写在目标仓库 `AGENTS.md`（或 `GEMINI.md`）里的一个小节，把整套流程每一步都要用到的事实固定下来：快测怎么跑、合并前跑什么、哪些目录高风险、哪些目录不能手改。写好之后，`saki-explore`、`saki-plan`、`saki-code-review` 以及 Antigravity 插件的 `PreToolUse` 禁改拦截钩子会直接读取，不用每次重新猜。

## 1. 格式

在 `AGENTS.md`（没有时用 `GEMINI.md` 或 `CLAUDE.md`）里加一个标题含 `saki-dev` 的小节，每行一个条目，命令和路径用反引号包起来：

```markdown
## 开发约定（saki-dev）

- 快测：`pytest tests/{target} -q`
- 重测：`pytest -m slow`
- 门禁：`make ci`
- 高风险：`src/storage/**`、`src/auth/**`、`migrations/`
- 禁改：`vendor/`、`src/generated/**`
- 重构建：`native-core/`（可选：仅改到这里才需重编重型子产物）
- 文件上限：`500`（可选：代码文件防膨胀上限，默认 500 行）
```

| 条目 | 英文写法 | 含义 | 必填 |
| --- | --- | --- | --- |
| 快测 | `quick-test` | 改完一个模块后跑的秒级测试命令；建议包含 `{target}` 或 `--changed` 按改动缩圈 | 是 |
| 重测 | `full-test` | 端到端、全量集成、重计算回归等慢测试 | 否 |
| 门禁 | `merge-gate` | 合并前跑一次的完整检查（全量测试、类型检查、构建或打包冒烟） | 是 |
| 高风险 | `high-risk` | 改到这里就走独立深审的目录；支持 `*`、`**`，以 `/` 结尾表示整个目录 | 是 |
| 禁改 | `do-not-edit` | 生成代码、vendored 第三方代码等不允许手改的目录（Antigravity 插件启用时 `PreToolUse` 钩子也会事前拦截） | 否 |
| 重构建 | `heavy-build` | 改到这里才需要重编重型子产物或原生模块的目录；未命中时默认复用缓存 | 否 |
| 文件上限 | `file-limit` | 单个代码文件的行数上限整数（默认 500，新建文件默认 400），用于审查防膨胀告警 | 否 |

书写规则：

- 小节从标题开始，到下一个同级或更高级标题为止；代码块里的内容不计入。
- 条目名可以加粗，冒号中英文都行；多个值分别用反引号包住。
- 英文仓库可写 `## Dev profile (saki-dev)` 并使用英文条目名。
- 控制在 12 行以内：它是常驻规范的一部分，每次对话都会加载。

## 2. 谁在用、怎么用

| 组件 / Skill | 用法 |
| --- | --- |
| `saki-explore` | 结构快照直接展示这一节，确认测试、重构建范围与文件上限时以它为准 |
| `saki-plan` | 快测、门禁、禁改、重构建触发与文件上限直接写进验证标准和派发契约；高风险目录按中途升级规则处理 |
| `saki-code-review` | 采集脚本标出高风险、禁改、重构建触发目录与超过 `文件上限` 且净增的文件；高风险一律走独立深审 |
| `saki-govern` | 体检时检查必填项、快测命令是否带缩圈过滤、失效目录规则以及超上限代码文件规模 |
| `hooks.json`（Antigravity 插件） | 在 `edit_file` / `write_file` 写入前直接拦截命中 `禁改`（`do-not-edit`）的路径 |

## 3. 怎么生成

1. 运行 `AUDIT_REPO --scope all`，从 `defined_scripts`（package.json、Makefile、justfile、`scripts/` 与 `ci_run_steps`）里找测试与检查命令。
2. **快测**：找能按模块或文件过滤的命令，实际跑一次，确认几秒到几十秒内完成，再把过滤部分换成 `{target}`。找不到可过滤的入口时，在体检报告里提出来，建议先补一个（见测试治理）。
3. **门禁**：优先使用 CI 里实际执行的那组命令；没有 CI 时，用仓库已有的全量测试加构建命令。
4. **高风险**：从下面几类里挑出仓库中真实存在的目录，再请用户确认增删：
   - 数据存储格式、数据库结构与迁移、缓存与同步
   - 鉴权、权限、支付、密钥与个人数据处理
   - 文件删除、批量覆盖等不可逆操作
   - 并发、异步与后台任务调度
   - 对外 API、CLI 参数、配置文件格式、SDK 公共接口
   - 打包、发布、安装与升级流程
   - 快照中改动频繁的超大文件
5. **禁改**：生成代码目录与 vendored 第三方代码。被 Git 忽略的目录本来就不会出现在改动里，不用写。
6. 起草后给用户看，确认后再写入 `AGENTS.md`。之后目录改名、新增高风险模块或测试入口变化时，同步更新这一节；体检报告提示“匹配不到任何文件的高风险目录”时，优先处理。
