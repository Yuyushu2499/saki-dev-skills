# saki-ship

`SKILL_DIR` 指当前 Skill 的绝对目录；`<python>` 指 Python 3.10+（macOS/Linux 通常为 `python3`，Windows 通常为 `py -3`）；`SHIP_HELPER` 是 `<python> "$SKILL_DIR"/scripts/ship_helper.py` 的简写。

## 核心规则

- **中文提交信息规范**：采用 `Conventional Commits` 英文类型前缀（`feat`、`fix`、`refactor`、`docs`、`test`、`chore`、`perf`、`style`）+ **简体中文描述**；仅必要的专有技术名词、符号名、文件名、缩写（如 `API`、`CLI`、`PR`、`Hook`）保留英文。
  - 示例：`feat(auth): 新增 token 过期自动刷新逻辑`、`fix(export): 修复跨时区报表日期偏移一天的问题`
- **先过测试再交付**：提交前必须确认与本次改动相关的验证测试已经通过；若刚在当前会话跑通且之后无代码变动，不重复空跑；若尚未验证，先跑局部快测或合并门禁。
- **开发分支自动提交推送，保护分支必须确认**：
  - 当前位于非保护开发分支（如 `dev`、`feat/*`、`fix/*`、`refactor/*`），且安全检查无敏感文件告警、无远端冲突时：直接完成暂存、提交并推送到远端（首次推送自动 `git push -u origin <branch>`）。
  - 当前位于 **`main` / `master` 保护分支**，或检测到疑似敏感文件（如 `.env`、密钥、凭据），或存在与本次任务无关的脏改动、或远端分支落后/冲突时：**立刻停下并把详情交给用户确认**，绝不静默直推主干或擅自 `--force`。
- **绝不把敏感信息与临时产物带入提交**：不盲目 `git add -A` 把 `.env`、密钥、日志、临时调试脚本一并提交；按文件核对变更清单。

## 工作流

### 1. 运行交付前安全检查

```text
SHIP_HELPER --workspace "<项目路径>"
```

脚本会客观输出：当前分支名、是否为保护分支（`main` / `master`）、上游跟踪状态（是否未设置 upstream、领先/落后提交数）、已暂存/未暂存/未跟踪文件列表，以及疑似敏感或临时文件告警。

### 2. 核对测试与改动边界

1. 确认本次功能/修复对应的测试已通过（若未跑过，先运行局部快测或项目约定的验证命令）。
2. 检查改动文件列表：
   - 若存在疑似敏感文件（`sensitive_warnings`）或明显不属于本次任务的无关文件，停止自动提交，向用户说明并确认处理方式。
   - 若没有任何可提交改动，直接提示工作区干净（若存在尚未推送的本地提交，直接询问或按分支规则推送）。

### 3. 编写中文提交信息并按分支安全策略执行

- 总结本次真实改动，生成简洁明确的中文提交信息（标题 ≤ 72 字符；多点重要改动可附简短中文正文）。
- **分支策略判定**：
  - **非保护开发分支**（如 `dev`、`feat/*`、`fix/*`）且无告警：
    1. 精确暂存本次相关文件（如 `git add <files>` 或确认全部改动均属本次任务后 `git add -A`）；
    2. `git commit -m "<type>: <中文描述>"`；
    3. 推送云端：已有 upstream 时执行 `git push`，无 upstream 时执行 `git push -u origin <当前分支>`。
  - **保护分支（`main` / `master`）或存在告警/远端冲突**：
    - 展示当前分支、拟提交文件清单、拟用中文提交信息与风险提示，**等待用户明确同意**（或由用户选择新建开发分支）后再执行提交/推送。
    - 推送遇 `non-fast-forward` 冲突时立刻停止并汇报，**严禁擅自 `--force` / `--force-with-lease`**。

## 输出与停止条件

完成后简明汇报：分支名、提交短哈希、中文提交信息、推送目标（如 `origin/dev`）以及是否已同步到云端；若因保护分支或告警暂停，清晰列出待用户确认的问题后停止。
